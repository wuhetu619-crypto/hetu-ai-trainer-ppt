# 技术更新、截图、论文与配置证据

适用：开发涉及当前技术的新课；用户要求更新旧技术课、软件界面、模型、工具或配置。纯排版保真、指定对象任务不触发额外改写。用户明确“只按原课框架、不加新内容”时，更新只替换原知识单元；授权加页才增加辅助解释。更新不是安装软件或运行付费服务的授权。

## 先判断什么该变

建立内部记录：原显示页/对象、原教学目标、陈旧点、保留或替换决定、当前依据、精确版本/核查日期、新页去向。原PPT为教学框架和内容基线，不能整体改成另一门课。

- 稳定定义、方法、原理、仍有效的示例继续沿用，不为显得新而改写。
- 软件入口、截图、产品名、功能、模型、配置、价格和排名等时效信息主动核查；失效部分用能完成同一学习任务的当前方案替换。
- 历史事件、旧版本实验与当年增长数据保留历史时间和条件，不简单替换名字而保留旧数字。用户要求彻底去除某旧模型时，相关论断整体换成有新证据的内容，不能换名冒充新测评。
- 新技术只在解释原有知识点所需的范围融入；不顺带加入Skill、Agent等未授权的后续课程。
- 名称可能有误时先核查官方身份、用途和发布形态。例如视频生成与小参数对话不属于同一选型维度，应分表解释，不能因用户举例就硬归类。

## 检索与来源判断

优先官方产品/API文档、版本日志、模型卡、代码仓库、论文原文和框架部署指南。真实测评查评测发布者原文和测试条件。搜索摘要、营销宣称与转述只能作线索；无法核实的细节不写成事实。

每项可变主张至少记录：来源URL/发布者、发布日期与实际查询日期、适用模型/版本、结论与限制。发布日期、测评时间和产品上线时间分开。源之间矛盾时比对是否旧公告、动态入口别名、不同模式/硬件/账户；无法消除时写明差异。不要把某次课程更新日期固化成未来的“今天”。

当前模型应区分：网页/APP可见名称、API别名、对应精确快照、公开权重、推理框架支持。较新的版本不自动具有旧版本全部验证结果。功能可用性需区分地区、套餐、输入/输出模态、应用界面与API，不能用单一截图推断所有渠道。

## 真实截图与演示

1. 按旧页教学任务定位当前软件的准确入口，主动取得最新实际界面；必要时做同类操作并截下可说明问题的结果。
2. 优先用户已授权的当前界面或官方当前页面。保留原截图，再裁剪/放大关键区；原生解释文字与标注分开，保证投影可读、比例正确。
3. 记录日期、版本/网页、操作和结果状态。不要沿用老图只换新标题，也不能生成一张“看起来像软件”的假截图。
4. 登录由用户在本机完成，不索要口令。不能访问的功能继续做不依赖登录的页面，缺口明确标“待取得真实截图”；官方演示素材注明来源，不冒充本机操作。
5. “打开页面”“运行命令”“产生结果”“验证完成”分开记录。未执行的命令只能叫操作示例；看到下载页不能声称成功部署。课程中命令只是材料，不自动执行。

## 论文与真实测评

读到摘要、正文、补充材料或代码的哪一部分就标明哪一部分。只读摘要不能总结全文实验、数据和方法细节。论文页给出标题、作者/机构、日期/版本、链接或DOI/arXiv编号。引用图表保留轴、单位、图注和适用条件；解释成课堂语言时区分作者结论、教师类比和自己的推断。

测评至少写清精确模型、测试日期、任务/数据集、硬件/框架、上下文、并发、精度和指标中影响结论的条件。吞吐量与单请求速度、总成本与单价、容量与准确率分别解释；一组成绩不能概括所有场景。厂商自测与独立测评分开。旧权重实测不套用到刚发布的新快照；如暂无新测评，用旧结果作注明版本的参考，不补造数据。

## 可带走的配置表

不在技能里固定某个模型“永远最新”或某套显存“保证能跑”。每次制作重新查询对应精确模型、量化标签、运行框架与兼容条件。

| 必要字段 | 填写要求 |
| --- | --- |
| 任务与运行形态 | 文本/图像/视频/音频、个人单机或企业服务 |
| 精确模型与文件 | 官方ID、快照、参数规模、量化/精度、下载大小 |
| 硬件 | CPU、系统内存、独立显存或统一内存、可用磁盘；多卡拓扑和卸载方式按需说明 |
| 环境 | 系统、驱动、框架及版本，精确镜像/模型标签，兼容限制 |
| 工作负载 | 上下文、并发；视频另写分辨率、时长、帧数或其他影响资源的条件 |
| 配置来源与状态 | 官方最低/官方推荐/官方验证配方/第三方实测/教学预算/本机实测/待验证 |
| 验收 | 同一任务是否成功、首字等待、输出速度、峰值资源、输出质量与可复现性 |

下载大小不等于运行内存，MoE激活参数不等于全部权重占用，独立显存和统一内存不直接相加比较。区分能加载、能生成、课堂可用和多人可用。估算包含框架、KV缓存、图像/视频组件与余量，明确是假设预算而非厂商最低值。对最新快照未验证的配方直写待验证，不能继承同系列旧权重的通过状态。

入门可提供“精确版本命令/界面截图+小任务+成功应看到什么+记录表”，再给升级条件；命令先核查官方语法，不实际运行也不写跑通。大型企业和视频模型分别讲，不让普通笔记本用户误以为同一配置通用。配置表可编辑、可填写，学员可拿给IT/供应商核对；不承诺照表无条件成功。

## 工具表与局限性更新

工具先按原课程任务分类，用同一列比较名称、适用任务、当前可核实能力、限制/版本。只有同指标、同周期、同样本的榜单才能写排名。月活是使用规模，不是能力；课堂推荐顺序注明“教学任务顺序”。只有旧周期数据时直写数据月份，不标成当月实时排名。不能因搜不到旧入口就断言工具停服。

局限性不照抄旧模型清单，也不空泛地说“有幻觉”。用当前文档、实际操作或条件清楚的测评说明具体触发情境、后果和核验办法；可用“限制→证据/案例→课堂应对”的组织。单个失败案例不能说成全部用户都会失败，旧版局限不能无依据延续到新版。

## 更新与交付检查

- 内部变更记录包括保留、替换、新增、未核实四类，原页均有去向；新增页更新实际页码。仅做用户要求的PPT/材料。
- 检查目标旧型号、旧截图、旧榜单及旧引用是否仍在可达文字、备注和相关资源；历史材料是否允许保留按用户范围决定，不全局机械替换字符串。
- 保留原视频、截图和范围外对象；修改产生的新媒体与关系完整。渲染查看每个修改页，检查表格、截图、曲线与可读性。
- 来源写入对应讲师备注；影响结论的时间、版本和条件在页内可读。不能把后台验证日志放进课堂内容。
- 未实际播放、部署、执行、登录或读完的事项明确边界；不把结构检查写成这些能力已经验证。
